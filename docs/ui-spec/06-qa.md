# 06 · QA 验收规则

> 这一层回答“什么算通过、谁来验、怎么验、存量差距怎么办”。
> 规范不降低验收线：新增/改动的 UI 必须达线；存量差距登记在 §6.5，按优先级收敛。

---

## 6.1 角色与时机

| 角色 | 验什么 | 时机 |
| --- | --- | --- |
| 设计师 | 信息层级、状态完整性、文案长度、双语排版 | 设计稿评审 / 实现走查 |
| 开发 | token、组件契约、键盘、busy、错误处理 | 提交前自检 |
| 测试 | 6 档视口、200% 缩放、键盘全程、简繁、异常流 | 功能测试 / 回归 |
| 产品/业务 | 文案准确性、流程可理解性、不可逆操作后果 | 验收 |

**设计稿准入**：只画默认态不收；必须带 hover/focus/disabled/loading/error + 空/失败/无权限/离线/长文案。
**代码准入**：`check:i18n`、`check:ui`、`lint` 全绿；新增页面有对应走查记录。

> 即使使用成熟组件库，也不能默认组件适配本项目的字体、语言、浏览器和数据。
> 组件库的单元/a11y 测试不能替代本项目的真实环境 Design QA（Google 无障碍指南同样强调这一点）。

## 6.3 手工验收矩阵

每个新页面/改版至少跑一遍：

| 维度 | 档位 | 看什么 |
| --- | --- | --- |
| 视口 | 360 / 640 / 720 / 900 / 1024 / 1440 | 不横向滚动、卡片列数、表格换行、筛选堆叠、弹窗不溢出 |
| 方向/分屏 | 手机横屏 720×360、桌面分屏 1024×700 | 顶栏/抽屉切换正确；弹窗高度可用；不出现横向滚动 |
| 缩放 | 200% 浏览器缩放 | 文字不裁切、按钮不重叠、弹窗可操作、表格不重叠 |
| 语言 | zh-CN / zh-TW | 不溢出、不截断、无 key、日期/编号一致 |
| 键盘 | 只用 Tab/Shift+Tab/Enter/Space/Esc/方向键 | 每个交互可达、焦点可见且不被顶栏遮住、弹窗焦点不逃、关闭后回到触发点 |
| 读屏 | NVDA/Edge 或 VoiceOver/Safari 抽测 | 页面有 h1、表单有 label、图标按钮有名字、状态有文字 |
| 高对比 | Windows 强制颜色模式 | 文字/边框/焦点仍可见，装饰可消失 |
| 动效 | 系统开启“减少动态效果” | 打字机/卡片/弹窗不闪烁、不阻塞；关键信息不依赖动画出现 |
| 网络 | 慢网 + 接口失败 + 断网/恢复 | 加载态、失败态 + 重试、不误报空；离线横幅与写操作禁用 |
| 长文案 | 40 字用户名、100 字标题、`zh-TW` 最长句 | 不溢出、不遮挡、不丢关键信息；按钮/表格/弹窗可重排 |
| 权限 | 不同角色（admin/reviewer/user） | 导航项/按钮/字段按权限显示，不出现 403 白屏 |
| 真实环境 | 真实后端数据 + 真实字体/浏览器 | 不是只看设计稿/Storybook；布局、状态、文案与实现一致 |
| 打印 | 浏览器打印预览 | 只打印内容、单页/分页合理、QR/编号完整 |

### 6.3.1 键盘路径必测

1. 顶栏：菜单（移动端）→ 铃铛 → 语言 → 头像 → 退出。
2. 侧栏：每个署 + 管理台；当前项有 `aria-current`。
3. 列表：筛选 → 表格行内操作 → 分页。
4. 弹窗：打开后焦点在弹窗内；Tab 循环；Esc 关闭；关闭后回触发按钮。
5. 表单：Tab 顺序与视觉一致；错误字段可被读到；提交按钮 Enter 可触发。
6. 站内信：消息卡 Enter 打开；未读状态有文字。
7. 上传：键盘可选择文件/删除；上传中/失败可感知。
8. 焦点遮挡：Tab 到顶部/首行元素时，焦点环不能被 sticky 顶栏、Toast 或浮层盖住；必要时页面自动滚动。

### 6.3.2 异常流必测

- 列表接口 500：显示错误 + 重试，不显示“暂无数据”。
- 提交接口 409/422：弹窗保持打开，字段/ toast 显示可读文案。
- 双击提交：只发一次请求（busy 生效）。
- 会话过期：自动刷新或回登录，不丢当前页数据（按现有 client 行为）。
- 附件下载 401/403：提示无权限，不暴露路径。
- SSO 取消：回门户，不进入半初始化页面。
- 联动非本人/未找到：不写入表单值，提示原因。
- 断网后提交：保留表单值，提示离线，不假装成功；恢复网络后可重试。
- 长查询/上传取消：点击取消后停止 loading、恢复按钮，已上传/已填内容不丢。
- 长文案：把用户名/标题替换为 40/100 字，检查顶栏、按钮、表格、弹窗不溢出。
- 页面刷新/回到列表：筛选、页码、滚动位置符合预期；不出现“成功但数据没变”。

## 6.4 对比度实测

### 6.4.1 方法

按 WCAG 2.2 相对亮度公式计算：

```
L = 0.2126 R + 0.7152 G + 0.0722 B   （R/G/B 先做 sRGB 线性化）
contrast = (Lmax + 0.05) / (Lmin + 0.05)
```

验收线：

- 普通文字（<18.66px/700 且 <24px）：**≥4.5:1**
- 大号文字（≥18.66px/700 或 ≥24px）：**≥3:1**
- 非文本 UI（控件边界、图标、焦点）：**≥3:1**（对相邻颜色）

### 6.4.2 通过的基础组合

| --- | --- | --- | --- | --- |
| 主文字 / 页面 | `#794f27` | `#f8f8f0` | 6.65:1 | ✅ 正文 |
| 卡片正文 | `#725d42` | `#f7f3df` | 5.61:1 | ✅ 正文 |
| 主文字 / 次级面 | `#794f27` | `#f0e8d8` | 5.82:1 | ✅ 正文 |
| 主文字 / 主色浅底 | `#794f27` | `#e6f9f6` | 6.50:1 | ✅ 正文 |

## 6.6 上线前检查

### 6.6.1 快速自检（11 问）

1. 页面是否有明确的第一视觉层级和主要操作？
2. 颜色是否全部来自 Token，而不是页面里随手新增？
3. 正文文字与背景对比度是否足够（4.5:1 / 3:1）？
4. 关键组件是否覆盖 hover / pressed / focus / disabled / loading / error？
5. 可点区域是否符合目标平台（Web 24 最低，项目 32/44）？
6. 只用键盘能否完成核心流程（含焦点不被顶栏遮住）？
7. 不同窗口宽度与横竖屏下信息是否仍然完整？
8. 文字放大或文案变长后，是否出现遮挡、截断、按钮溢出？
9. 空、错误、权限不足、断网是否都有处理？
10. 设计工具里的组件是否能与代码组件/变体一一对应？
11. 是否在真实环境做过 Design QA，而不是只对截图？

### 6.6.2 Definition of Done

一个页面/组件只有同时满足以下条件才算“完成”：

#### 视觉

- [ ] 只用 `--animal-*` / `--nl-*` / 规范常量；无裸 hex/rgb（打印/QR 例外）。
- [ ] 交互元素圆角 ≥12px；按钮/输入 pill；Card 20px；Modal blob；Title 飘带。
- [ ] 3D 阴影只在 primary/danger-primary；Card 无阴影；Switch 无外阴影。
- [ ] 文字角色来自 Foundations §2.2；屏幕 UI ≥12px；无纯黑/冷灰。
- [ ] 状态标签 `soft` + 允许色；彩色卡承载文字用 pattern。
- [ ] 设计稿里的每个组件都能在代码中找到对应组件/变体；没有一次性变体。

#### 交互

- [ ] 默认/hover/focus/active/disabled/loading/error 七态齐全（按组件矩阵）。
- [ ] 异步按钮 busy + disabled；成功后关窗 → toast → 刷新。
- [ ] 不可逆动作走 `ConfirmAction`；有后果说明。
- [ ] 空/加载/失败/离线/无权限/长文案分开；失败可重试。
- [ ] 长任务可取消/后台继续；原子提交不提供“取消一半”。
- [ ] 弹窗 `maskClosable={false}`；Esc 可关；焦点进入/返回正确。
- [ ] 表格 `table-fit`；无横向滚动；分页只在 `total > pageSize` 时出现。

#### 无障碍

- [ ] 正文 4.5:1、大号 3:1、非文本 3:1（按 §6.4 组合）。
- [ ] 键盘全程可达；焦点可见、≥3:1、不被 sticky 顶栏/浮层遮挡；无键盘陷阱。
- [ ] 每页一个 h1；表单有 label；图标按钮有 aria-label；图片有 alt。
- [ ] 200% 缩放 + 360px 宽不丢内容/不横向滚动。
- [ ] 触控目标 ≥32×32（密集）/44×44（主操作），视觉与可点区域分清。
- [ ] `prefers-reduced-motion` 下动画可关闭；Typewriter 不承载关键信息。

#### 双语与内容

- [ ] 所有可见文案 `t()`；`zh-CN`/`zh-TW` 键一致。
- [ ] 切到 zh-TW 不溢出/不截断/无 key；最长文案 +30% 仍可用。
- [ ] 服务端内容有 `_tw` 列；后台表单成对编辑；空值回退。
- [ ] 错误/空状态文案说明“发生了什么 + 下一步”，不显示原始错误码。

#### 工程与交付

- [ ] `npm run check:i18n` / `check:ui` / `lint` 全绿。
- [ ] 相关 smoke 通过。
- [ ] 新增/修改 token 已同步 `tokens.json` 与 [02 Tokens](./02-tokens.md)。
- [ ] 新增偏差已登记 §6.5；修复的偏差已更新状态。
- [ ] 交付包含页面/组件/token/状态/响应式/交互/异常/文案/验收条件（见 README §4.5）。
- [ ] 真实环境 Design QA 已做：真实数据、字体、浏览器、权限、慢网。

## 6.7 评审清单（按层）

| 层 | 三个必问 |
| --- | --- |
| Foundations | 颜色是否有唯一语义？文字角色是否来自表？状态是否不只靠颜色？ |
| Tokens | 有没有裸值？token 是否存在？tokens.json 是否同步？ |
| Components | 七个状态是否齐？尺寸是否同排一致？键盘是否可达？ |
| Patterns | 失败是否被误当空？离线/权限/长文案是否处理？确认/busy/toast 顺序是否对？ |
| Layouts | 360/720/1024 是否重排？200% 与长文案是否可用？表格是否横向滚动？ |
| QA | P0 是否清零？新偏差是否登记？真实环境 Design QA 是否做过？ |

### 6.7.1 常见失败模式

| 失败模式 | 表现 | 预防 |
| --- | --- | --- |
| 只规定视觉，不规定交互状态 | 默认态统一，hover/focus/error 各写各的 | 用 §6.6.2 七态清单验收 |
| 把设计稿尺寸当规则 | 某个画板像素不动，换宽度就崩 | 用间距尺度、容器逻辑、断点重排 |
| 组件变体太细 | 每个页面一个新按钮，库比页面还难维护 | 先找重复决策；一次性样式不进组件库 |
| 忽略长文案/国际化 | 中文正常，繁体/英文上线即溢出 | 用 zh-TW 最长句 +40/100 字测试 |
| 无障碍放到最后 | 颜色/结构定型后再补，成本翻倍 | 对比度/焦点/键盘/触控从设计稿开始 |
| 规范没人维护 | 组件改了三版，文档还是旧截图 | token/组件变更同步本文；偏差登记有状态 |
